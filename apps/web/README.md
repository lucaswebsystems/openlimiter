# OpenLimiter website

This Next.js project is intentionally independent from the backend workspace.

Run `pnpm install` and `pnpm build` from this directory. In Vercel, set the project root directory to `apps/web`. The local `vercel.json` selects the Next.js framework.

## Performance

Measured 2026-09-07 with `OL_DIST_DIR=.next-sonnet npx next build`, before and after this pass. Numbers below are bytes on disk in the build output, not gzip.

- **A pre-existing build blocker was fixed first.** `next build`'s own generated route type check refused `app/app/cli/page.tsx`'s default export, which took optional `client`/`session`/`initialCode` props for testing: Next requires a page's default export to accept nothing but `params`/`searchParams`, and separately refuses a page module with any export beyond its own whitelist. Neither `npx tsc --noEmit` nor `vitest` catches this, since it is a check `next build` runs on its own. Fixed by moving the actual component into `app/app/cli/cli-page-view.tsx` (named export `CliPageView`) with `page.tsx` reduced to a thin default export that renders it with nothing; the same pattern was used for the new `app/app/openrouter/callback` route. Without this fix, `next build` could not complete at all, so none of the numbers below could have been measured.
- **`experimental.serverMinification` re-enabled.** The 2026-08-11 follow-up recorded a crash prerendering `/app` with this on; it no longer reproduces; `next build` completes cleanly (108/108 static pages) with it on. `/app`'s server bundle (`server/app/app/page.js`): 302,015 bytes unminified, 72,575 bytes minified, a 76% cut. This is server bundle size only, never a byte a visitor's browser downloads.
- **Per-route message namespace loading.** `NextIntlClientProvider` (`components/site-html.tsx`) now takes a `namespaces` prop instead of one fixed list for every tree. The marketing and docs tree's default (`MARKETING_CLIENT_NAMESPACES`) drops `hub` (7.7 KB of the 126.9 KB catalog), which it never hydrates a component that reads from; `/app` (`app/app/layout.tsx`) passes its own list dropping `proPortal` (4.3 KB) and `localeSwitcher` (0.02 KB), which it never does either, since the language switcher is off on that route. The catalog's two largest namespaces, `docs` (58.7 KB) and `privacy` (15 KB), were already server rendered only and never reached the client provider on any tree, before or after this change; the actual savings here are real but modest; see `components/site-html.tsx` for the measured breakdown.
- **Hub polling cadence** (`lib/hub-polling.ts`, wired into `app/app/dashboard.tsx`): the hub previously had no periodic background refresh at all, only mount, window focus and a manual Sync click. It now polls every 60 seconds while a device wrote within the last 15 minutes, every 5 minutes otherwise, is paused entirely while the tab is hidden (resuming with one immediate read when it becomes visible again), and never has more than one request in flight, since the poll is rescheduled only once the previous one's answer has already landed.
- **The `app/app/engine` mirror (376 KB) was not touched.** `apps/web` carries its own `pnpm-workspace.yaml` (`packages: ["."]`), separate from the root workspace (`packages: ["packages/*"]`), so it cannot import `packages/ui` or `packages/core` without adding them as cross-workspace dependencies, a `package.json` and lockfile change outside this pass's remit (another lane owns `packages/`, and this pass was instructed not to touch it or `apps/desktop`). The mirror's own header confirms this is deliberate: it is generated by `app/app/engine/sync.mjs` specifically because the package source is not importable from here directly. Deleting or reconciling it needs that workspace boundary addressed first.
